# AIMP Telegram Cloud Provider (WebDAV-based)

Проект плагина-прослойки для воспроизведения музыкальной библиотеки из Telegram напрямую в плеере **AIMP** через встроенный интерфейс «Мои облака» (Custom WebDAV).

---

## 📌 Идея и концепция

У вас уже есть готовый плагин для Total Commander (написан на **C#** с использованием библиотеки **WTelegramClient**), который загружает аудиофайлы в Telegram и сохраняет структуру каталогов и метаданные в базе SQLite `base.db`.

Данный проект расширяет эту систему для **AIMP**, добавляя поддержку полноценной фонотеки, плейлистов, обложек и перемотки треков (Seek) без необходимости запускать сторонние программы вручную.

---

## 🏗️ Архитектура системы

Приложение объединяет C# сервер и WebDAV-интерфейс в единый плагин для AIMP:

```
┌─────────────────────────────────────────────────────────────────┐
│                          Процесс AIMP                           │
│                                                                 │
│ ┌───────────────────────┐             ┌───────────────────────┐ │
│ │  Интерфейс AIMP       │  WebDAV     │  AIMP C# Plugin DLL   │ │
│ │  (Мои облака/WebDAV)  │ ──────────> │                       │ │
│ └───────────────────────┘ HTTP 206    │ ┌───────────────────┐ │ │
│                                       │ │  Встроенный       │ │ │
│                                       │ │  WebDAV Server    │ │ │
│                                       │ └─────────┬─────────┘ │ │
└───────────────────────────────────────┼───────────┼───────────┼─┘
                                        │           │           
                                        ▼           ▼           
                                ┌──────────────┬──────────────┐
                                │ WTelegram    │ SQLite       │
                                │ Client       │ (base.db)    │
                                └──────┬───────┴──────────────┘
                                       │
                                       ▼
                             [ Telegram MTProto API ]
```

### Ключевые компоненты:
1. **AIMP Plugin DLL Wrapper (C# / Native AOT)**:
   * Нативная DLL, загружаемая AIMP при старте из папки `Plugins/`.
   * Автоматически поднимает WebDAV-сервер при запуске AIMP и аккуратно гасит его при закрытии.
2. **Встроенный WebDAV / HTTP Сервер**:
   * Слушает локальный порт (например, `http://localhost:37000/`).
   * Обрабатывает методы: `PROPFIND` (структура папок и файлы), `GET` (стриминг аудио), `HEAD`, `OPTIONS`.
   * Поддерживает `HTTP 206 Partial Content` (перемотка треков и чтение заголовков).
3. **WTelegramClient Bridge**:
   * Отвечает за асинхронное скачивание фрагментов файлов из Telegram (`Client.DownloadFileAsync`).
4. **Кэш метаданных SQLite (`base.db`)**:
   * Хранит виртуальную файловую структуру, идентификаторы сообщений Telegram, распарсенные ID3-теги и обложки.

## ⚡ Технические узкие места (Bottlenecks) и их решения

### 1. Перемотка и Range-запросы (Seek & Partial Content)
* **Проблема**: Аудиодекодер AIMP запрашивает фрагменты файла произвольными кусками (`Range: bytes=1048576-2097151`).
* **Решение**: WebDAV-сервер транслирует HTTP-диапазоны байт в вызовы `WTelegramClient.DownloadFileAsync(file, stream, offset, count)` с выравниванием по блокам Telegram (128КБ / 512КБ).

### 2. Защита от бана Telegram (Flood Wait) при сканировании фонотеки
* **Проблема**: При добавлении папки из 500+ треков AIMP пытается параллельно открыть все файлы для чтения ID3-тегов. Если штурмовать Telegram сотнями запросов — Telegram заблокирует аккаунт (`FLOOD_WAIT`).
* **Решение**: 
  * Метаданные (артист, название, альбом, длительность, обложка) считываются библиотекой `ATL.NET` / `TagLib#` при загрузке трека и **кэшируются в `base.db`**.
  * Кэширование первых 128 КБ заголовка файла в SQLite. `PROPFIND` и `HEAD` отдают данные мгновенно из локальной базы, **0 сетевых запросов к Telegram** при поиске и открытии папок.

### 3. Оптимизация памяти (RAM)
* **Проблема**: Риск раздувания оперативной памяти при стриминге больших lossless файлов (FLAC/WAV).
* **Решение**: Использование `ArrayPool<byte>.Shared` и кольцевых буферов (64 КБ - 512 КБ). Файлы не загружаются в память целиком. Общий объем RAM плагина — в районе **20–35 МБ**.

### 4. Конкурентный доступ к SQLite
* **Проблема**: Одновременный доступ к `base.db` из плагина Total Commander и плагина AIMP.
* **Решение**: Перевод SQLite базы в режим WAL (`PRAGMA journal_mode=WAL;`) и использование таймаутов блокировок.
