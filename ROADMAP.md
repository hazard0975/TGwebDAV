# ROADMAP & Progress Tracker (Universal WebDAV & Network Drive Service)

Документ отслеживания этапов разработки универсального C# WebDAV-сервиса и сетевого диска Telegram.

Архивная дорожная карта версии V1 (AIMP Plugin) сохранена в файле: [`ROADMAP_V1_AIMP_PLUGIN.md`](./ROADMAP_V1_AIMP_PLUGIN.md).

---

## 📌 Текущий статус проекта
- **Фаза**: Реализованы все модули C# сервиса: база данных SQLite WAL, WebDAV сервер, WTelegramClient с защитой FLOOD_WAIT, парсер тегов ATL.NET, TrayContext и форма настроек WinForms.
- **Целевая платформа**: Windows Desktop / C# (.NET 8.0/9.0) Tray App & Background Service.
- **Протокол**: WebDAV (`http://localhost:{port}/`, настраиваемый порт) + Автомонтирование сетевого диска (`Z:`, `T:`, `Y:`, `W:` или авто-выбор).

### [x] Этап 2: Универсальный C# WebDAV Сервер

- [x] Реализация XML-ответов `PROPFIND` с привязкой к SQLite.
- [x] Реализация записи, версионирования и управления: `PUT`, `MKCOL`, `DELETE`, `MOVE`.
- [x] Логика обработки перезаписи файлов: сохранение прежней версии как `v1` в корзину и присвоение текущему файлу версии `v2`.
- [x] Виртуальное отображение папки корзины (`Z:\.Trash` / `Z:\Корзина`) и механизм восстановления предыдущих версий. Исправлен баг отображения файлов в `.Trash` (добавлена умная выборка `is_deleted = 1` при чтении корзины).
- [x] Зеркалирование структуры каталогов в корзине: при удалении файлов или вложенных папок сохраняется их точный исходный путь внутри `.Trash` (например, `Z:\.Trash\Album\CD1\track.mp3`), предотвращая свалку файлов в корне корзины и потерю структуры папок при удалении через Проводник Windows.
- [x] Реализация полноценного перманентного удаления: при очистке корзины `.Trash` или удалении файлов из нее, данные сначала стираются из Telegram (включая рекурсивное пакетное удаление группами по 100 сообщений для папок с сотнями файлов для защиты от Flood Wait и таймаутов), а затем строки физически удаляются из SQLite базы данных.
- [x] Отказоустойчивое пакетное удаление из Telegram с бинарным делением (Биссекция): при возникновении ошибок типа `MESSAGE_ID_INVALID` (например, для файлов, удаленных ранее вручную в клиенте Telegram) пакет делится пополам, позволяя успешно и быстро удалить все валидные сообщения за минимальное число обращений к API.
- [x] Исправление первопричины появления дубликатов в корзине: универсальная обработка двухэтапного создания файлов Проводником Windows (0-байтовый плейсхолдер) и плагином WebDAV Total Commander (1-байтовый pre-flight probe). Файлы $\le 1$ байта больше не отправляются в Telegram впустую и не улетают в корзину при наполнении реальным содержимым, а обновляются на месте с версией 1. При необходимости 1 байт сохраняется локально в SQLite и отдается клиентам без обращения к Telegram.
- [x] Исправление бага восстановления/перемещения (`MoveNode`): корректный сброс флага `is_deleted = 0` при переносе из корзины и установка `is_deleted = 1` при переносе в корзину с рекурсивным обновлением вложенных элементов папок.
- [x] Реализация заголовков `Accept-Ranges: bytes` и статуса `206 Partial Content` для быстрой перемотки и докачки файлов на ПК.
- [x] Оптимизация под Проводник Windows: полная реализация виртуальных Mock-блокировок (`LOCK`, `UNLOCK`) и обновления свойств (`PROPPATCH`) для 100% стабильной бесконфликтной совместимости с Проводником без пустых файлов и ошибок копирования.
- [x] Защита от прямой записи в корзину: строгая блокировка запросов `PUT` и `MKCOL` внутри каталога `/.Trash` со статусом `403 Forbidden` для предотвращения случайной загрузки файлов в Telegram и рассинхронизации состояния базы.
- [x] Защита системной корзины от случайного уничтожения (Вариант 1): блокировка удаления (`DELETE /.Trash`) и перемещения/переименования (`MOVE /.Trash`). При массовом удалении файлов в корне (Ctrl+A -> Delete) запрос на удаление самой корзины завершается статусом `204 NoContent` без уничтожения данных, позволяя клиентам (Проводник, Total Commander) безопасно переместить все пользовательские файлы в `.Trash`, сохранив их структуру и защитив от безвозвратного стирания в Telegram. Перманентное удаление файлов внутри корзины (`DELETE /.Trash/*`) сохраняет свою работоспособность.
- [x] Чистый корень диска и интеграция корзины в Windows Shell:
  - Скрытие `.Trash` из листинга корня диска при `PROPFIND` (опция `HideTrashFromRoot`, по умолчанию включена). Корень диска остаётся чистым, исключая случайное выделение корзины при Ctrl+A.
  - Нативная интеграция корзины в контекстное меню Проводника Windows (`ShellContextMenuHelper`): пункт «Открыть корзину WebDAV» с системной иконкой корзины (`shell32.dll,31`) с умным фильтром `AppliesTo` (пункт отображается исключительно при правом клике по сетевому диску или внутри его каталогов, не засоряя диски C:, D: и Рабочий стол; ветка `HKCU`, без требования прав администратора).
  - Пункт быстрого перехода «Открыть корзину (Z:\.Trash)» в меню системного трея приложения возле часов.
  - Настройки и переключатели «Скрывать папку .Trash из корня диска» и «Пункт "Открыть корзину WebDAV" в контекстном меню Windows» во вкладке «Сервер и Диск» окна настроек `AuthSettingsForm`.
